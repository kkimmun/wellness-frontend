S3 장소 이미지 연동 설명

1. 구현 목적

관리자가 장소를 생성할 때 선택한 이미지를 multipart/form-data의 imageFiles로 전송하고,
백엔드는 기존 FileService와 S3Service를 통해 S3의 places 디렉터리에 저장한다.
조회 시에는 프론트가 IMG_PATH와 SAVE_NAME을 직접 조립하지 않아도 되도록
백엔드가 완성된 imageUrl을 반환하고 화면은 해당 URL을 사용해 이미지를 표시한다.


2. 기존 백엔드 로직 확인

- AdminPlaceController: @ModelAttribute와 imageFiles를 받아 장소 생성/수정 요청 처리
- AdminPlaceService: 장소 INSERT 후 imageFiles를 순서대로 업로드하고 PLACE_IMG 저장
- FileService: 이미지 확장자와 MIME 타입을 검증하고 UUID 파일명 생성
- S3Service: AWS SDK S3Client로 places/{저장파일명} 키에 객체 업로드
- 업로드 또는 DB 저장 실패 시 이미 올라간 S3 객체를 삭제해 불완전한 파일이 남는 것을 방지

위 업로드 흐름은 팀 최신 코드에 이미 구현되어 있어 그대로 유지했다.

4. 백엔드 응답 변경

- 지도 전체 핀: GET /api/places/pins
- 타입별 핀: GET /api/places/types?type={값}
- 태그별 핀: GET /api/places/tags?tag={값}

위 응답의 각 장소에 활성 이미지 중 IMG_ORDER가 가장 빠른 이미지의 imageUrl이 포함된다.

- 관리자 장소 상세: GET /api/admin/places/{placeNo}

placeImages 각 항목에 IMG_PATH || SAVE_NAME으로 만든 imageUrl이 포함된다.
기존 imgPath, saveName, originalName, imgOrder 필드는 호환을 위해 유지한다.


5. 사용 기술

5.1 multipart/form-data

텍스트 필드와 여러 이미지 파일을 한 요청에 함께 보내는 HTTP 전송 형식이다.
관리자 장소 생성/수정에서 imageFiles를 같은 키로 여러 번 추가해 이미지 순서를 보존한다.

5.2 AWS SDK for Java S3Client

백엔드가 AWS S3 버킷에 객체를 저장하고 실패한 업로드 객체를 삭제할 때 사용한다.
프론트는 AWS 자격 증명을 가지지 않으며 백엔드가 반환한 S3 URL만 사용한다.

5.3 MyBatis 대표 이미지 조회

PLACE_IMG에서 DEL_YN='N'인 이미지 중 IMG_ORDER와 IMG_NO가 가장 빠른 항목을
KEEP (DENSE_RANK FIRST ...)로 선택한다. 따라서 삭제된 이미지나 순서가 뒤인 이미지를
대표 이미지로 잘못 반환하지 않는다.
