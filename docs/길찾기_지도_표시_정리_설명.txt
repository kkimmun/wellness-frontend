길찾기 지도 핀 및 이전 경로 잔상 해결

1. 문제
- 길찾기 결과가 표시된 뒤에도 DB 장소 핀 전체가 계속 보여 경로 확인이 어려웠다.
- 대중교통, 자동차, 도보를 연속 선택하면 이전 이동수단의 일부 선이 지도에 남았다.
- 이동수단 변경 직전에 보낸 요청이 늦게 완료되면 이전 경로가 다시 선택될 가능성이 있었다.

2. 원인
- MapPage가 경로 선택 여부와 관계없이 filteredPins 전체를 MapMarker로 렌더링했다.
- 여러 Polyline과 단일 Polyline 사이를 전환할 때 카카오 지도 객체 일부가 완전히 제거되지 않았다.
- clearRouteResult가 화면 상태는 비웠지만 진행 중인 일반 경로 요청은 중단하지 않았다.

3. 해결
- 경로 결과가 없을 때만 일반 DB 핀을 표시한다.
- 경로 결과가 있으면 응답의 origin, waypoints, destination만 지도 핀으로 표시한다.
- RoutePolylineLayer가 자신이 만든 Kakao Polyline 객체를 배열로 관리한다.
- 경로나 이동수단이 바뀌면 기존 객체에 setMap(null)을 호출한 뒤 새 경로만 생성한다.
- 입력 또는 이동수단 변경 시 진행 중인 경로 요청을 AbortController로 즉시 중단한다.
- 길찾기 패널 옆 원형 화살표는 입력과 결과를 유지한 채 패널만 숨기거나 다시 연다.
- 패널의 X는 출발지·도착지·경유지·경로를 모두 초기화해 길찾기를 종료한다.
- 초기 타입/태그 선택 안 함 상태에서는 핀을 표시하지 않고, 전체 선택 버튼을 눌러야 전체 장소를 표시한다.
- 전체 선택 버튼을 다시 누르면 전체 선택을 해제하고 핀이 없는 선택 안 함 상태로 돌아간다.

4. 변경 파일
- src/features/map/MapPage.jsx
  표시할 핀을 경로 상태에 따라 구분하고 선언형 Polyline을 전용 레이어로 교체했다.

- src/features/map/components/RoutePolylineLayer.jsx
  카카오 Polyline 생성과 명시적 정리를 담당하는 전용 컴포넌트를 추가했다.

- src/features/map/components/RoutePanel.jsx
  결과 초기화 시 진행 중인 이전 경로 요청도 중단하도록 수정했다.
