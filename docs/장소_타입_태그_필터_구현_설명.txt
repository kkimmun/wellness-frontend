장소 타입·태그 지도 필터 구현 설명

1. 구현 목적

지도 화면에서 사용자가 DB에 저장된 장소 타입 또는 태그를 선택하면,
해당 조건과 일치하는 장소만 지도 핀과 장소명 검색 대상으로 표시한다.

연동 API

- GET /api/places/types?type={타입 또는 상세 타입}
- GET /api/places/tags?tag={태그}

두 API 모두 로그인하지 않은 사용자도 사용할 수 있는 조회 API다.


2. 사용 기술

2.1 Axios query parameter

무슨 기술인가?

Axios 요청의 params 옵션으로 URL query parameter를 만드는 기능이다.

왜 사용했는가?

타입과 태그에 한글이 포함되어 있으므로 문자열을 직접 URL에 이어 붙이는 것보다
Axios가 URL 인코딩을 처리하도록 하는 것이 안전하다.

어떻게 사용했는가?

api.get("/places/types", { params: { type } })
api.get("/places/tags", { params: { tag } })


2.2 React 상태 관리

무슨 기술인가?

useState로 전체 핀, 현재 필터의 핀, 지도에 실제 표시하는 핀을 구분해 관리한다.

왜 사용했는가?

필터를 해제했을 때 백엔드에 전체 핀을 다시 요청하지 않고 기존 전체 핀을 복원하고,
타입·태그 필터 결과 안에서 장소명 검색도 계속 사용할 수 있게 하기 위해서다.

어떻게 사용했는가?

- pins: 최초 /api/places/pins 결과
- filterPins: 타입 또는 태그 API 결과
- filteredPins: 지도에 현재 표시하는 결과
- activeFilter: 현재 선택된 필터의 종류와 값


2.3 요청 순서 보호

무슨 기술인가?

useRef에 요청 번호를 저장하고 최신 요청과 응답 번호가 같은지 확인하는 방식이다.

왜 사용했는가?

사용자가 필터를 연속으로 빠르게 변경하면 먼저 보낸 요청이 나중에 도착할 수 있다.
이전 응답이 최신 필터 결과를 덮어쓰지 못하게 하기 위해 적용했다.

어떻게 사용했는가?

필터 요청마다 filterRequestIdRef 값을 증가시키고,
응답 시점에 현재 번호와 다르면 그 응답을 화면에 반영하지 않는다.

- 타입과 태그 중 한 조건만 선택하도록 상태 구성
- 필터 API 결과로 지도 핀과 SearchPanel 검색 대상을 함께 변경
- 전체 보기 선택 시 최초 전체 핀 복원
- 좌표가 없는 응답 데이터는 지도 핀에서 제외
- 필터 결과가 한 곳이면 해당 위치로 이동하고, 여러 곳이면 전체 결과가 보이도록 지도 범위 조정
- 필터 결과가 없거나 요청이 실패하면 기존 공통 Modal로 안내
- 연속 요청의 응답 순서가 바뀌어도 최신 결과만 반영

- 이전 검색 결과가 화면과 지도에 남는 문제 방지


4. 입력값 규칙

타입은 다음 두 종류를 모두 사용할 수 있다.

- TYPE.TYPE: 주요관광지, 의료기관, 관광지, 생활체육시설, 종교시설, 음식점
- TYPE_DETAIL.TYPE_DETAIL: 역사유적, 자연명소, 종합병원, 한의원, 체험형,
  전시형, 실내체육시설, 야외운동시설, 사찰, 성당교회, 뷔페, 생선회,
  일식, 술집, 중식, 패스트푸드, 탕류

태그는 TAG.TAG_CONTENT에 저장된 16개 고유 값을 사용한다.

주의:

- 템플스테이와 가족동반은 현재 TAG 테이블에 없는 값이므로 선택 목록에 넣지 않았다.
- 가족 관련 조회는 가족 또는 유아동반을 선택한다.
- 장소가 연결되지 않은 타입은 API가 정상적으로 빈 배열을 반환하며 화면에서 안내한다.


5. 검증 결과

- 수정 파일 대상 ESLint: 성공
- Vite production build: 성공
- 전체 프로젝트 ESLint는 기존 코드 31건의 선행 오류로 실패
- 백엔드 타입·태그 API 39개 DB 값: HTTP 200 및 중복 placeNo 0건 확인
- 로컬 브라우저 테스트 시 localhost:5173에 수정 전 프론트 서버가 이미 실행 중이었음
- 별도 127.0.0.1 서버는 카카오 앱 등록 도메인과 달라 지도 SDK가 차단됨
- 기존 localhost 서버는 사용자 작업 보호를 위해 종료하지 않음
